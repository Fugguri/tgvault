## 0.5.0 — 2026-10-14

### Добавлено

- **Команда `view` — просмотр сообщений за период без импорта.** Читает историю
  напрямую из Telegram и печатает её текстом в stdout: логи на диск не пишутся,
  медиа не качается. Быстрый способ дать агенту контекст, когда раскладывать чат
  по дням не нужно.
  - Цель: `-entry <slug>` (запись конфига) либо `-chat` / `-id` / `-alias` (+ `-topic`).
  - Период: `-from` / `-to YYYY-MM-DD` (границы включительно; без них — последние
    7 дней) или `-last N` — последние N сообщений.
  - Лимиты: `-max-len N` — обрезка одного сообщения (дефолт 1500, хвост `…(+N симв.)`),
    `-max-msgs N` — максимум сообщений в выводе (дефолт 200, берутся последние).
  - Медиа: по умолчанию пометки (`🖼 [фото]`, `🎤 [голосовое 0:12]`, `📎 [документ: …]`);
    `-media` — скачать вложения в `~/.cache/tgvault/view/` и печатать абсолютные пути;
    `-transcribe` — распознать голосовые локально (whisper).
  - Вывод — markdown: `# чат`, строка периода, дни (`## дата`), сообщения
    `**HH:MM — автор**`, ответы с превью `↩ msg:N — «…»`.

## 0.4.1 — 2026-10-13

### Изменено

- **Согласование выполняет агент, а не пользователь.** `tgvault approve <id> -y`
  работает без терминала: агент показывает текст пользователю и после явного «да»
  согласует сам — пользователю не нужно ничего запускать. Из настоящего терминала
  `approve` по-прежнему спрашивает `[y/N]`.
  - Строгий режим `TGVAULT_APPROVAL=strict` (или `TGVAULT_REQUIRE_TTY=1`) —
    опция для тех, кому нужна «стена»: тогда `-y` не действует и согласовать
    можно только из терминала человека.

## 0.4.0 — 2026-10-13

### Добавлено

- **Согласование исходящих действий.** `send`, `manage … -send` и `bot -go`
  теперь выполняются только с одноразовым согласованием, привязанным к хэшу
  содержимого (цель + текст + файлы + параметры). Без согласования команда
  регистрирует запрос и отказывает с его id.
  - `tgvault approve <id> [-ttl 5m]` — интерактивное подтверждение из терминала
    (`/dev/tty`); агенту недоступно. Согласование живёт TTL и расходуется один раз.
  - `tgvault pending` — очередь запросов (ожидает / ✓ согласовано).
  - Меняется текст или цель — другой id, старое согласование не подходит.
  - Пакет `internal/approve` + unit-тесты (детерминизм id, grant/consume,
    истечение, привязка к содержимому).

## 0.3.0 — 2026-10-13

### Добавлено

- **Команда `manage`** — управление чатами прямо из tgvault (по умолчанию
  dry-run; реальное действие — флаг `-send`). Люди задаются как
  `@username`, числовой `id` или телефон `+7999…`.
  - `manage create` — создать обычную группу, супергруппу (`-forum` — сразу с
    топиками) или канал (`-kind group|channel|chat`), опционально пригласить людей.
  - `manage topic` — создать форум-топик в супергруппе.
  - `manage forward` — переслать сообщения (`-msg ID…` или `-last N`), в т.ч. в
    конкретный топик назначения (`-dest-topic`), с `-drop-author`/`-silent`.
  - `manage invite` — добавить людей в группу/канал.
  - `manage rights` — выдать/снять права админа: пресеты `admin`/`moderator`,
    точечные `-rights a,b,c`, `-rank "…"`, `-revoke`.
  - `manage kick` — убрать из чата или забанить (`-ban`, `-days N`).
  - `manage delete` — удалить группу/канал, которыми владеешь.
- Общий резолвер цели `resolveChatTarget` (self / alias / id / часть имени)
  вынесен в `internal/cli/target.go`; `send` переведён на него.

## 0.2.0 — 2026-10-10

### Изменено

- **Транскрибация встроена в бинарь, внешний `whisper-cli` больше не нужен.**
  whisper.cpp собирается как статическая библиотека (`make whisper-libs` в
  `third_party/whisper.cpp/build_go`) и линкуется через cgo
  (`internal/transcribe/native.go`). Модель `ggml-*.bin` открывается прямо в
  процессе и грузится один раз, затем переиспользуется для всех голосовых.
  Аудио (ogg/opus) декодирует `ffmpeg` в PCM.
  - Удалены `internal/transcribe/whisper.go` и `whisper_server.go`, а также
    флаг `-whisper-bin`/`WHISPER_BIN`, `ResolveWhisper`, сборка `whisper-cli`
    и сервер `whisper-server`.
  - `tgvault setup` теперь только качает модели (ffmpeg по-прежнему нужен).
  - Сборка без cgo (`CGO_ENABLED=0`) компилируется, но транскрибация в ней
    отключена (заглушка `native_stub.go`).
  - Релизы собираются нативно под каждую ОС/арх (cgo не кросс-компилируется);
    `.goreleaser.yaml` убран, GitHub Actions собирает матрицей.

## 0.1.5 — 2026-10-10

### Добавлено

- **Вынос секретов из чатов.** При `import` tgvault ищет в переписке токены и
  ключи и заменяет их на ссылку `{{secret:<NAME>}}`, а значения складывает в
  `docs/telegram_chats/<slug>/.secrets.json` (права `600`, в `.gitignore`). Так
  агент, читая лог, видит только имя, а не сам ключ.
  - Паттерны: Telegram-бот-токен, OpenAI `sk-…`, GitHub `ghp_…`, Google `AIza…`,
    AWS `AKIA…`, Slack `xox…`, JWT, блоки `-----BEGIN … PRIVATE KEY-----`, а также
    `api_key`/`token`/`secret`/`password` со значением.
  - Имя детерминировано от значения (`tg_1a2b3c4d`), поэтому повтор одного
    секрета даёт одно имя, а не дубликаты.
  - Флаг `tgvault import -no-secrets` отключает вынос; `tgvault secret chat <slug>`
    показывает имена, `tgvault secret chat <slug> <NAME>` — значение (для скриптов).
  - Проверено тестами `internal/redact` и `internal/importer`.

### Изменено

- **Ключи остаются в `.env`, прячем только от LLM.** `tgvault` читает
  `api_hash`/`api_key` из `.env` как обычно (значения, не ссылки); а в своём
  выводе — `-h`, сообщения флагов по умолчанию, ошибки — заменяет значения
  переменных с «секретными» именами (`*API_HASH*`, `*API_KEY*`, `*API_ID*`,
  `*TOKEN*`, `*SECRET*`, `*PASSWORD*`, `*2FA*`, `PRIVATE_KEY`) на `{{secret:VAR}}`.
  `setup` снова пишет значения в `.env`. Хранилище `~/.secrets` для этого не
  требуется.

## 0.1.4 — 2026-10-08

### Добавлено

- **Секреты отдельно от кода (ссылки `{{secret:NAME}}`).** Ключи больше не лежат
  в `.env` открытым текстом: `tgvault` подставляет их из хранилища
  `~/.secrets/tgvault/<NAME>` (права `600`) на старте, а в `.env` остаётся только
  ссылка `{{secret:tgvault/NAME}}`. Так ключ не попадает ни в репозиторий, ни в
  контекст агента — видно только имя.
  - Новая команда `tgvault secret` — `set` (значение из скрытого ввода),
    `ls`, `ref`, `rm`, `check` (права, пустые значения, повторы).
  - Маскировка значений в выводе: если то же значение встречается под несколькими
    именами, в логах и `-h` оно заменяется на одно каноническое имя
    (короткое, затем лексикографически) — стабильно между запусками.
  - `setup` записывает `api_id`/`api_hash` в хранилище и оставляет в глобальном
    `.env` ссылки, а не значения.
  - Хранилище и область переопределяются `SECRETS_DIR` и `SECRETS_SCOPE`.
  - Проверено: 9 unit-тестов пакета `internal/secrets`, ручной прогон
    `secret set/ls/ref/check` и отсутствие утечки значения в `-h`.

- **Команда `tgvault update` — самообновление.** Тянет последний релиз с
  GitHub и атомарно заменяет исполняемый файл на месте, так что повторно
  запускать `install.sh` не нужно. `-check` показывает доступную версию без
  установки, `-force` переустанавливает. Версия вшивается в бинарь на релизе
  через `-ldflags -X main.version={{.Version}}`.
  - Раз в сутки (best-effort, не чаще) команды, работающие с Telegram,
    напоминают в stderr о новом релизе; отключается `TGVAULT_NO_UPDATE_CHECK=1`.
  - Проверено вживую: `update -check` увидел v0.1.3; тесты `internal/update`
    на сравнение версий, разбор ответа GitHub и атомарную замену файла.

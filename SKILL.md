# tgvault

Один бинарь `tgvault`: читает Telegram (MTProto), качает медиа, транскрибирует
голосовые локально и раскладывает переписку в Markdown.

## Правила (жёстко)

1. **Ничего не устанавливай** — ни `playwright`, ни `python`/`telethon`/`faster-whisper`.
   Всё нужное уже в `tgvault`. Нет бинаря — скажи пользователю, не ставь сам.
2. **Никогда не запускай `tgvault init`** — он интерактивный (TUI), ты его не сможешь провести.
   Для добавления чатов используй **`tgvault add`** (неинтерактивный).
3. **Не изобретай скрипты/обёртки** поверх `tgvault`.
4. **Не читай `.env`.** Ключи (`TG_API_HASH`, `TG_API_ID`, `GEMINI_API_KEY`, …) лежат
   в `.env` для самого бинаря; `tgvault` сам прячет их в своём выводе (`-h`, ошибки)
   как `{{secret:VAR}}`. Не открывай `.env` и не печатай значения.
5. **Не обновляй tgvault сам.** Заметил, что вышла новая версия — скажи пользователю
   `tgvault update`, не запускай обновление бинаря.
6. **Секреты из чатов уже спрятаны.** При импорте токены из переписки заменяются на
   `{{secret:NAME}}`, значения — в `docs/telegram_chats/<slug>/.secrets.json`. Не читай
   этот файл и не подставляй значения сам; нужен ключ — `tgvault secret chat <slug> NAME`.
7. **`manage` по умолчанию — dry-run.** Действие с побочным эффектом (создание чата/топика,
   пересылка, приглашение, выдача прав, кик/бан) выполняй только с `-send`.
8. **Перед отправкой ВСЕГДА спрашивай разрешение у пользователя.** Ничего не отправляй
   молча. `send`, `manage … -send`, `bot -go` требуют согласования, привязанного к
   точному содержимому. Порядок строго такой:
   1) запусти команду **без** `-send` — это превью, вывод даст `#id`;
   2) покажи текст пользователю и дождись явного «да»;
   3) выполни `tgvault approve <id> -y` — **это твоя работа**, не пользователя;
   4) повтори ту же команду с `-send`.
   Не согласуй без явного «да». Не меняй текст между согласованием и отправкой
   (согласование станет недействительным).
   **Согласование живёт 5 минут** (меняется флагом `-ttl`). Поэтому сначала получи
   «да», и только потом выполняй `approve`: если человек думал дольше, грант
   протухнет и `-send` откажет — тогда повтори `approve` и ту же команду с `-send`.
   (Пользователь может включить строгий режим `TGVAULT_APPROVAL=strict` — тогда
   согласовать можно только из его терминала; в этом случае попроси его.)

## Быстрый старт (делай ровно так)

Если в проекте уже есть `.tg-import.json` — сразу к «Импорт».
Иначе сначала добавь хотя бы один чат.

### Шаг 1. Добавить чат в проект

```bash
tgvault add -chat "часть имени чата"
```

`add` сам создаёт `.tg-import.json` и дописывает `docs/telegram_chats/` и
`.tg-import.json` в `.gitignore`. Дубли отклоняет.

Форум-топик (сначала узнай id):

```bash
tgvault topics "Mind"                 # покажет id и названия топиков
tgvault add -chat "Mind" -topic 112 -default
```

Полезные флаги: `-default` (тянуть каждый раз), `-note "…"`, `-when "…"`,
`-write-to "…"`, `-id <id-чата>`.

### Шаг 2. Посмотреть, что в проекте

```bash
tgvault list
```

### Шаг 3. Импорт

```bash
tgvault import                        # дефолтные записи (последние 30 дней)
tgvault import -entry Mind_Сториз     # одна запись
tgvault import -all -from 2026-09-01  # все записи, с даты
tgvault import -all -all-history      # все записи, вся история (осторожно: FLOOD_WAIT)
```

Без `-from` импорт берёт только последние 30 дней — не вытягивай всю историю
по умолчанию. Полная история — явно `-all-history` (тянет без окна, осторожно:
FLOOD_WAIT). `-full` — это полный пересбор логов с нуля: он тоже тянет всю
историю, но ещё и перезаписывает `_log.md`, поэтому как «просто посмотреть
историю» его не бери.

Результат — логи: `docs/telegram_chats/<slug>/upd_<дата>/_log.md`.

### Шаг 4. Сводка (обязательно после импорта)

После `import` **дай пользователю короткую сводку** по импортированному:

- прочитай свежие `docs/telegram_chats/<slug>/upd_<дата>/_log.md` (папка добавляется на каждый запуск);
- если сообщений немного (≈ до 50) — перескажи по пунктам: кто и что написал;
- если много — сгруппируй по темам/авторам и выдели важное: решения, задачи, вопросы, дедлайны, договорённости;
- история копится по папкам `upd_<дата>` (инкрементально, старое не перезаписывается) — для полной
  картины читай нужные дни/записи.

## Быстрый просмотр без импорта (`view`)

Когда нужен контекст «здесь и сейчас» (о чём писали за период), а импортировать чат
не надо — **`view`**: читает сообщения напрямую из Telegram и печатает их текстом в
stdout. Ничего не пишет на диск, медиа не качает (по умолчанию), логи не трогает.

```bash
tgvault view -chat "часть имени" -from 2026-10-07 -to 2026-10-14
tgvault view -entry Mind -last 50           # запись из конфига, последние 50
tgvault view -chat "Mind" -topic 112 -from 2026-10-01
```

- **Цель**: `-entry <slug>` (запись конфига) либо `-chat "имя"` / `-id <id>` / `-alias <slug>`,
  при необходимости `-topic <id>`.
- **Период**: `-from` / `-to YYYY-MM-DD` (границы включительно; без них — последние 7 дней)
  или `-last N` — последние N сообщений.
- **Лимиты**: `-max-len N` — обрезка текста одного сообщения (дефолт 1500, хвост помечается
  `…(+N симв.)`); `-max-msgs N` — максимум сообщений в выводе (дефолт 200, берутся последние).
- **Медиа** — по умолчанию только пометки: `🖼 [фото]`, `🎤 [голосовое 0:12]`, `🎬 [видео]`,
  `📎 [документ: имя]`. Чтобы получить файлы:
  - `-media` — скачать вложения в кэш (`~/.cache/tgvault/view/`) и печатать абсолютные пути
    (картинку агент откроет сам);
  - `-transcribe` (вместе с `-media`) — распознать голосовые локально (whisper).
- **Вывод** — markdown: `# чат`, строка периода, дни (`## дата`), сообщения
  `**HH:MM — автор**`, ответы `↩ msg:N — «превью»`.

`view` ничего не сохраняет: если история нужна в проекте — всё равно `import`.

## Если что-то не так

- **Нет бинаря `tgvault`** → сообщи пользователю, не устанавливай сам.
- **Ошибка авторизации** → попроси пользователя выполнить `tgvault login` (один раз, интерактивно).
- **Пустой конфиг / нет дефолтных записей** → добавь чаты через `tgvault add` (шаг 1), затем `import -all`.
- **Нет транскрипции голосовых** → whisper не настроен → попроси `tgvault setup`.
- **«Готово: 0 новых сообщений»** → не гадай: под итогом печатается строка
  «Ничего не импортировано» с причиной по каждой записи. «состояние актуально» —
  нового действительно нет; «в окне по умолчанию» — граница 30 дней, всю историю
  тянет `-all-history`; «диапазон не захватил» — поправь `-from/-to`.
- **«⚠ состояние … повреждено»** → битый `.tg-state.json`; предложи пользователю
  удалить файл и импортировать запись заново (уже выгруженное не продублируется —
  дедуп по `<!-- msg:ID -->`).

## Команды (шпаргалка)

- `add` — добавить чат/топик в конфиг (**для тебя**, неинтерактивно; создаёт конфиг и `.gitignore`).
- `import` — импорт (`-all`, `-entry <slug>`, `-from/-to YYYY-MM-DD`; вся история —
  `-all-history`, полный пересбор логов — `-full`). Без границ первый проход берёт
  последние 30 дней.
- `view` — просмотр сообщений за период **без импорта** (`-entry`/`-chat`/`-id`, `-topic`,
  `-from/-to`, `-last`, `-max-len`, `-max-msgs`; `-media` — пути к файлам, `-transcribe` — голосовые).
- `list` — компактная сводка записей проекта (где искать чат).
- `dialogs` — список диалогов (kind + id + имя).
- `topics "<чат>"` — форум-топики чата.
- `voice "<чат>"` — первое голосовое из последних 100 сообщений: скачать и распознать (`-topic`).
- `migrate` — старый конфиг v1 → v2 (только если он есть).
- `secret` — секреты из чатов: `chat <slug>` (имена), `chat <slug> NAME` (значение).
- `update` — обновиться до свежего релиза (только пользователь, см. правило 5).
- `init` — **интерактивный**, НЕ для агента.
- `send` — отправить/править/удалить сообщение (dry-run → согласование → `-send`).
- `manage` — чаты/топики/люди: `create`, `topic`, `forward`, `invite`, `rights`, `kick`, `delete`
  (dry-run → согласование → `-send`). Люди — `-user @name|id|+phone`.
- `approve <id> [-y]` / `pending` — согласование исходящего и очередь запросов.
  Агент выполняет `approve <id> -y` **после** явного «да» пользователя.
- `bot` — клик-тест бота (`-bot @user -step send:/start`; `-go` после согласования).

## Чего НЕ делать

- Не устанавливать зависимости (см. правило 1).
- Не запускать `init` (см. правило 2) — только `add`.
- Не гонять `import` ради разового «что писали за период» — для этого есть `view`
  (быстро, ничего не пишет на диск).
- Не перебирать диалоги для поиска чата: id/access_hash уже в конфиге. Разовый поиск — `dialogs`.
- Не переспрашивать, в каком чате смотреть: справочник (`note`/`when`) в `.tg-import.json` или `tgvault list`.

## Как это работает

- Сессия Telegram **глобальная** (`~/.config/tgvault/session.json`), вход один раз на машину.
- Запуски сериализованы локом: параллельные **ждут**, а не падают.
- Импорт инкрементальный (водяной знак `last_id` в `<slug>/.tg-state.json`), тянет только новое;
  правки/удаления — только через `-full`.
- `view` читает историю напрямую и на диск не пишет — быстрый способ дать контекст без импорта.
- Голосовые транскрибируются локально (whisper.cpp, модель `base`). Медиа — в `<slug>/files/`,
  привязано к сообщению (`<!-- msg:ID -->`).

# tgvault

Один бинарь `tgvault` делает всё: читает Telegram (MTProto), скачивает медиа,
транскрибирует голосовые локально и раскладывает переписку в Markdown.

## Главное правило

**Ничего не устанавливай.** Не ставь `playwright`, `python`, `telethon`, `faster-whisper`
и прочее. Всё нужное уже в `tgvault`. Если бинаря нет — сообщи пользователю, не лезь ставить сам.

## Что читать сначала

1. `tgvault list` — компактная сводка записей проекта: slug, чат/топик, `default`
   (что тянется каждый раз), справочник. Это самый быстрый способ понять,
   куда идти за импортом, **без чтения всего конфига**.
2. Конфиг проекта `.tg-import.json` (в корне, ищется вверх по дереву) — если нужны детали.
3. Уже собранные логи: `docs/telegram_chats/<slug>/upd_<YYYY-MM-DD>/_log.md`.

## Команды

- `tgvault import` — импорт **дефолтных** записей. Флаги:
  `--all` (все записи), `--entry <slug>` (одна), `--from/--to YYYY-MM-DD`, `--full` (пересбор с нуля).
- `tgvault list` — компактная сводка записей проекта (где искать чат, что дефолтное).
- `tgvault init` — создать/пересоздать конфиг проекта (интерактивный мастер, поиск `/`).
- `tgvault migrate` — перевести старый конфиг v1 в v2.
- `tgvault dialogs` — список диалогов (kind + id + имя).
- `tgvault topics "<часть имени чата>"` — форум-топики чата.

## Чего НЕ делать

- Не устанавливать зависимости (см. выше).
- Не перебирать диалоги, чтобы найти чат: id/access_hash уже в конфиге. Для разового поиска — `tgvault dialogs`.
- Не переспрашивать, в каком чате смотреть: смотри справочник (`note`/`when`) в `.tg-import.json`.
- Не плодить свои скрипты/обёртки поверх `tgvault`.

## Как это работает (чтобы не удивляться)

- Сессия Telegram **глобальная** (`~/.config/tgvault/session.json`), вход один раз на машину.
- Доступ к сессии сериализован локом: параллельные запуски **ждут**, а не падают.
- Импорт инкрементальный (watermark `last_id` в `<slug>/.tg-state.json`), тянет только новое.
  Правки/удаления — только через `--full`.
- Голосовые транскрибируются локально (whisper.cpp, модель `base`). Качество приемлемо для LLM.
- Медиа качается в `<slug>/files/`, привязано к сообщению (`<!-- msg:ID -->`).

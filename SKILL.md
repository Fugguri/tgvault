# tgvault

Один бинарь `tgvault`: читает Telegram (MTProto), качает медиа, транскрибирует
голосовые локально и раскладывает переписку в Markdown.

## Правила (жёстко)

1. **Ничего не устанавливай** — ни `playwright`, ни `python`/`telethon`/`faster-whisper`.
   Всё нужное уже в `tgvault`. Нет бинаря — скажи пользователю, не ставь сам.
2. **Никогда не запускай `tgvault init`** — он интерактивный (TUI), ты его не сможешь провести.
   Для добавления чатов используй **`tgvault add`** (неинтерактивный).
3. **Не изобретай скрипты/обёртки** поверх `tgvault`.
4. **Не читай значения секретов.** В `.env` стоят ссылки `{{secret:…}}`, значения —
   в `~/.secrets/tgvault/` (права 600). Подстановку делает `tgvault` сам; в логах и
   `-h` видно только ссылку. Если секрет нужен — `tgvault secret set NAME`, не
   открывай файл хранилища и не печатай значение.
5. **Не обновляй tgvault сам.** Заметил, что вышла новая версия — скажи пользователю
   `tgvault update`, не запускай обновление бинаря.

## Быстрый старт (делай ровно так)

Если в проекте уже есть `.tg-import.json` — сразу к «Импорт».
Иначе сначала добавь хотя бы один чат.

### Шаг 1. Добавить чат в проект

```bash
tgvault add -chat "часть имени чата"
```

`add` сам создаёт `.tg-import.json` и дописывает `docs/telegram_chats/` и
`.tg-import.json` в `.gitignore`. Дубли отклоняет.

Форум-топик (сначала узнай id):

```bash
tgvault topics "Mind"                 # покажет id и названия топиков
tgvault add -chat "Mind" -topic 112 -default
```

Полезные флаги: `-default` (тянуть каждый раз), `-note "…"`, `-when "…"`,
`-write-to "…"`, `-id <id-чата>`.

### Шаг 2. Посмотреть, что в проекте

```bash
tgvault list
```

### Шаг 3. Импорт

```bash
tgvault import                        # дефолтные записи
tgvault import -entry Mind_Сториз     # одна запись
tgvault import -all -from 2026-09-01  # все записи, с даты
```

Результат — логи: `docs/telegram_chats/<slug>/upd_<дата>/_log.md`.

### Шаг 4. Сводка (обязательно после импорта)

После `import` **дай пользователю короткую сводку** по импортированному:

- прочитай свежие `docs/telegram_chats/<slug>/upd_<дата>/_log.md` (папка добавляется на каждый запуск);
- если сообщений немного (≈ до 50) — перескажи по пунктам: кто и что написал;
- если много — сгруппируй по темам/авторам и выдели важное: решения, задачи, вопросы, дедлайны, договорённости;
- история копится по папкам `upd_<дата>` (инкрементально, старое не перезаписывается) — для полной
  картины читай нужные дни/записи.

## Если что-то не так

- **Нет бинаря `tgvault`** → сообщи пользователю, не устанавливай сам.
- **Ошибка авторизации** → попроси пользователя выполнить `tgvault login` (один раз, интерактивно).
- **Пустой конфиг / нет дефолтных записей** → добавь чаты через `tgvault add` (шаг 1), затем `import -all`.
- **Нет транскрипции голосовых** → whisper не настроен → попроси `tgvault setup`.

## Команды (шпаргалка)

- `add` — добавить чат/топик в конфиг (**для тебя**, неинтерактивно; создаёт конфиг и `.gitignore`).
- `import` — импорт (`-all`, `-entry <slug>`, `-from/-to YYYY-MM-DD`, `-full`).
- `list` — компактная сводка записей проекта (где искать чат).
- `dialogs` — список диалогов (kind + id + имя).
- `topics "<чат>"` — форум-топики чата.
- `migrate` — старый конфиг v1 → v2 (только если он есть).
- `secret` — хранилище ключей: `set NAME`/`ls`/`ref NAME`/`rm NAME`/`check`.
- `update` — обновиться до свежего релиза (только пользователь, см. правило 5).
- `init` — **интерактивный**, НЕ для агента.
- `send` — отправить/править/удалить сообщение (dry-run по умолчанию; реально — флаг `-send`).
- `bot` — клик-тест бота (`-bot @user -step send:/start -go`).

## Чего НЕ делать

- Не устанавливать зависимости (см. правило 1).
- Не запускать `init` (см. правило 2) — только `add`.
- Не перебирать диалоги для поиска чата: id/access_hash уже в конфиге. Разовый поиск — `dialogs`.
- Не переспрашивать, в каком чате смотреть: справочник (`note`/`when`) в `.tg-import.json` или `tgvault list`.

## Как это работает

- Сессия Telegram **глобальная** (`~/.config/tgvault/session.json`), вход один раз на машину.
- Запуски сериализованы локом: параллельные **ждут**, а не падают.
- Импорт инкрементальный (водяной знак `last_id` в `<slug>/.tg-state.json`), тянет только новое;
  правки/удаления — только через `-full`.
- Голосовые транскрибируются локально (whisper.cpp, модель `base`). Медиа — в `<slug>/files/`,
  привязано к сообщению (`<!-- msg:ID -->`).
